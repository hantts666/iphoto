附件是产品构想和评审材料，其中的开发步骤不直接视为本轮启动编码的指令。上一轮建议也不自动转换为用户确认。

**需求草案：以下均为提议，需根据回答取舍**

| ID | 需求 | 初步验收 |
| --- | --- | --- |
| R-01 | 导入单张照片，正确处理方向与输入色彩信息；格式按 Q-12 确认 | 方向测试图和带 ICC 的照片显示正确；原文件内容哈希不变 |
| R-02 | 一句话提出修图目标，返回可以理解和修改的建议 | 建议只包含已经实现的能力；不接受任意代码或未知算子 |
| R-03 | 人像、风景、室内通用的全局曝光/阴影/高光、对比度、偏色和饱和度调整；按场景增加局部增强 | 三类照片分别盲评；无明显色阶断裂、光圈、严重偏色或不合理压暗 |
| R-04 | 参数微调、原图对比、撤销与重做 | 快速调参不显示过期结果；后续 AI 不覆盖锁定的用户字段 |
| R-05 | 适合窗口预览和真正的 100% 图像区域查看 | 100% 区域来自原图管线，不放大缩略图冒充细节 |
| R-06 | 保存和重新打开编辑项目 | 参数、必要蒙版和用户修改可恢复；原图移动后可重新定位 |
| R-07 | 导出原分辨率 sRGB JPEG，不覆盖原图 | 方向、尺寸、输出 profile 正确；目标冲突有明确处理 |
| R-08 | 云端失败后仍能手调和导出 | 超时、Key 错误、Schema 错误不破坏当前项目 |
| R-09 | 上传内容可理解、密钥不进入项目和日志 | 网络请求只有允许的缩略图/裁剪；日志检查通过 |
| R-10 | 在约定 Windows 环境独立安装运行 | 无预装 Python 的干净环境完成导入、编辑、保存和导出 |

候选延后项：生成式重绘、液化、眼周专修、磨皮、复杂降噪、RAW、批处理、照片库、云同步、个人风格学习。Q-03 的答案可能改变其中部分内容，不提前认定用户已同意延期。

第 1 轮对计划的实质影响：先建设通用全局调整引擎，三类场景均建立测试集；人脸模块成为可选增强，不能让无脸照片无法完成主流程。交互采用“导入 → 输入目标 → 生成建议并渲染 → 对比/继续描述或微调 → 导出”，不默认导入即启动 AI 优化。

需求确认条件：Q-01 至 Q-08 中影响架构的事项已有回答或用户明确接受的默认值；R 条目已完成取舍；实际照片测试与交付目标已有可执行安排。无需用户逐个批准内部函数名或目录名。
