# iPhoto V1 执行计划草案

状态：用户已要求开始制作，已完成一个可试用的本地原型。已确认自用、Windows 优先、Qt/PySide6 和通用单图修图。格式、云端服务、痛点与最终质量标准仍待补充。

当前进度：P03–P05、P08–P10 已完成原型所需的子集；未宣称整个工作包验收。P02 仅完成本机运行环境与依赖，未做独立安装包；P06 完成合成 24MP 负载基准，未做真实照片质量盲评。P11 已实现可操作 AI 设置、Windows 凭据存储、千问 Token Plan 独立适配和异步视觉参数规划，模拟接口与界面流程已验证，真实账号鉴权、费用和质量仍待实际 Key 联调。P07 人脸定位、P12 AI 质量评估、P13 干净系统发布验收未实施。详见 [原型验证记录](../../docs/prototype-validation.md) 与 [AI 连接指南](../../docs/ai-connection.md)。

执行单位是一个可以独立检查的工作包。每包记录依赖、实现范围、交付文件和验收证据。图像质量失败先定位到算子、蒙版或建议层，不通过增加 UI 功能绕过。进度以验收结果为准，当前不承诺未经估算的发布日期。

**任务顺序与交付物**

| ID | 工作包 | 前置条件 | 具体交付物 | 验收和失败处理 |

| P09 | 实现第一版桌面编辑流程 | P08 | 导入、画布、原图对比、参数、蒙版预览、100% 区域、导出入口 | 使用固定/手动参数完成可操作闭环；UI 不被计算阻塞 |

P02/P03、P07/P08 等无依赖部分可以在工程安排上交错进行；这不代表已创建并行任务或授权多个代理。默认在当前项目逐包落实。

**三个关键决策门槛**

- G1（P06）：固定参数能否在人像、风景、室内产生自然、稳定的色调与颜色调整？局部提亮单独验收。未通过时优先调整算子和蒙版；必要时比较 darktable/RawTherapee 适配成本。
- G2（P12）：AI 是否比保守本地预设更有用？不能仅用 Schema 通过率判定；同时记录人工评分、需要返工的次数、延迟和调用成本。
- G3（P13）：离开开发机是否能可靠使用？模型、运行库、项目恢复、导出和错误处理都必须实测。

任何门槛失败都留下样片或可复现步骤、原因假设和下一项有限修正，不重复无目标地调 Prompt。

**第一轮验收提议**

| 项目 | 方法 | 候选通过条件 |
| --- | --- | --- |
| 非破坏式编辑 | 导入前后、编辑后、导出后比较源文件 SHA-256 | 原文件完全未变 |
| 零调整 | 同一解码/色彩参考下比较像素，不比较重新编码的 JPEG 文件字节 | 核心无隐藏调整；输出量化差异在定义范围内 |
| 图像方向和色彩 | 覆盖 EXIF 方向夹具、sRGB/其他 ICC 与缺失 profile 样例 | 方向正确；profile 处理与文档一致 |
| 参数安全 | 非法 JSON、未知字段、NaN/Infinity、极值和坏蒙版引用 | 均不进入渲染；当前项目保持可用 |
| 样片效果 | 匿名排序，评价自然度、人物突出、偏色与光圈 | 每张有结果和失败原因；具体通过比例与用户在 Q-09 确认 |
| 预览与导出 | 对照全分辨率输出下采样，另检查 100% 原图区域 | 无明显颜色/局部区域跳变；容差由固定参考定义 |
| 复现 | 同原图、Recipe、蒙版、引擎与后端重复渲染 | 固定环境下像素一致；不同后端如支持则单设容差 |
| 性能 | 指定硬件、固定样片、重复采样，冷启动和热缓存分开 | 候选热预览 P95 ≤ 500ms；24MP 导出 ≤ 15s；全进程树峰值 ≤ 1.5GiB，待 Q-08/P06 确认 |
| 异步正确性 | 快速调参、撤销、换图、取消、导出时继续编辑 | 结果绑定正确 revision；无旧结果覆盖 |
| 云端失败 | 模拟超时、认证失败、非法建议，再做真实 API 抽查 | 本地编辑和导出仍可用；Key 和图片内容不进入日志 |
| 项目恢复 | 保存/重开、源图移动、worker 意外退出 | 已提交状态不损坏，失败有可操作的恢复提示 |
| 分发 | 无 Python/开发依赖的 Windows 环境 | 可安装、启停、导入、编辑、保存、导出 |

这些是待确认的验收方法和门槛，没有任何一项声称已经测试通过。样片人工评价不能被测试用例数量替代。

**计划如何随着 QA 调整**

如果首发要求 RAW，新增相机样本、RAW 解码/显影、相机色彩与高位深输出任务，重估 P04–P06；如果要求批处理，新增批次状态、逐图失败隔离与并发预算；如果首发公开发布，新增供应商额度/滥用控制、分发与升级方案。它们不作为几个开关塞进当前排期。

Q-04 已选定 Qt/PySide6，P02 仅验证这条路线，不再安排 Tauri 对比原型。

完成 QA 后，根据交付优先级给工作包排序和估算；先公布第一个可试用里程碑的范围，再根据 P06 的实际速度估算后续工期。
