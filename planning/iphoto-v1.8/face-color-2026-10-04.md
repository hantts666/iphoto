# 第九十四轮：人脸定位、面部操作与色彩通道

## 问题头

1. 全局分析未把人脸独立列出；文字直选走通用主体分割，不能可靠区分脸、皮肤和帽子。
2. 磨皮要先理解选区与输出图层；缺少可直接操作的气色与面部精修入口。
3. 只有全局冷暖、色偏与饱和度，无法独立控制通道或单独修改一种颜色。
4. 人脸定位点可能落在帽檐；已有语义孔洞经通用修边可能被填入。
5. “边缘色彩保护”滑杆没有参与合成，操作不会产生承诺的效果。

## 架构与操作修改

- YuNet 在照片打开的图像进程内做1280px本地人脸定位；检测框与定位点只提供身份和上下文。没有结果时用同一神经模型处理±30°旋转输入，再映射回原图。权重显式安装、固定大小/摘要，窗口不下载。
- 场景与文字协议明确 `object / face / face_skin`。画面分析合并本地脸清单，缓存恢复同样补齐；同位置重复云端脸被合并，其他未检测的云端脸仍保留。
- 完整人脸由 BiSeNet 的面部类分区，保留五官，排除颈部、帽子、头发、衣物；面部皮肤排除模型识别到的五官。由本地检测定位但锚点被遮挡时，只允许在该人脸提示范围内找到模型实际预测的鼻部；没有时失败保留旧范围。
- 人脸/皮肤叠加图揭示1605帽檐下及1608一侧眼睛仍被当作皮肤。追加YuNet五官定位保护，与分区类别核对后只保护可见的合理眼/口区域；帽子、背景与鼻部上的眼部猜测不扩展。实际三图重新走完原入口流程，范围外0、原像素/导出/保存/撤销一致，原应用/父进程0，已查看新叠加图。保护椭圆会连带少量邻近皮肤，不能当完美语义边界。
- “选人脸 / 只选皮肤”与“磨皮 / 提气色 / 自然精修”可直接调用。后三者自动建立局部层，重复调用复用对应面部层，保留其他参数；隐藏层不被悄悄显示。精修是自然平滑、明暗与轻锐化，不是脸型重塑或自动祛痘。
- AI 自动面部分区与已检测的唯一人脸关联，复用原图面部上下文；多人有歧义时继续原有云端放大定位。一张实图的对话磨皮/气色由两阶段简化为一次云端规划、本地分区与自动建层。
- 蒙版保存 `semantic_target`，AI 与经典修边均向内处理已有语义零覆盖度，保护五官与范围外像素。移除没有实际作用的色彩保护滑杆。
- Recipe 从13项扩展为40项：RGB三通道增益与八色HSL各三项；共享范围验证、AI schema、参数锁、历史、项目、预览、原像素图块、导出。HSL选择器只展示当前色段三项，切换前提交输入，AI修改能定位实际参数，折叠状态不重置。
- RGB使用精确256级每通道查表；HSL使用有界条带浮点计算，避免大角度旋转使用粗3D查表造成颜色误差。转换参考 [W3C CSS Color 4](https://www.w3.org/TR/css-color-4/#hsl-to-rgb)，色段权重与调整政策为本项目定义。相邻色段循环余弦过渡，灰色与未参与色段保持。RGB增益不是曲线。
- 版本与项目协议1.9，可读取0.1以及1.2～1.8旧文档，新参数项目不能交给旧版读取。

模型依据：[OpenCV YuNet](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet)、[检测接口与15列输出](https://docs.opencv.org/4.13.0/df/d20/classcv_1_1FaceDetectorYN.html)、[BiSeNet 作者实现](https://github.com/yakhyo/face-parsing)。这些来源支持模型接口与组合设计，不能代替本项目照片的精度验收。
