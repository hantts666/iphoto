# 第一百零一轮：面部精修连续操作与图层身份

## 问题头

1. 快捷面部入口依赖图层名称和蒙版标签。用户改名后再提气色会新建重复层，原磨皮层叠加保留；1605实际界面已复现两层变三层。
2. 手动修边会把范围标签改为“手动选区”，AI也可以自定义图层名。名称不能承担人脸身份；需要保存对应关系并保留用户修改过的范围。
3. 透明边缘细化和经典重新贴边生成新位图时可能丢失关联。经典代理优化也不能填回神经皮肤范围内的细小排除区域。
4. 不能因层名相似，把另一人脸、另一照片、鼻部小层、反选、修复层当成整脸调整层。新增关联也必须支持草稿撤销和项目持久化。

## 架构修改

- 蒙版增加可选 `face_binding`，仅有 `face_id` 和原图 `source_sha256`。验证身份和64位十六进制源摘要，规范化摘要大小写；只允许全脸/皮肤语义蒙版携带。它不参与alpha或颜色计算。
- 本地完整人脸入口、匹配到已知脸的AI完整皮肤分层、完整文字选脸成功结果都记录关联。部位选择不推断整脸关联，异步返回先检查照片摘要。文字完整选脸在记录草稿历史之前附加身份。
- 快捷入口按对应人脸与源摘要寻找普通皮肤调整层，优先当前选中层，再考虑最近的匹配层；保持用户名称、已修范围、其他参数和其他图层。排除反选、修复/填充与组。旧蒙版没有关联时，只认可原完整皮肤标签，成功复用后迁移；不猜测改过标签的旧层身份。
- 补选、擦除沿用原蒙版关联；重选、清空和全选建立新范围，清除原人脸关联。ViTMatte及PyMatting细化保留非反选关联，反选输出不带面部语义/关联。经典重新贴边对面部/身体皮肤限制在原范围，输出原尺寸alpha并保留原像素排除孔洞。
- 应用1.9.7，项目协议仍1.9。实际执行main提交b077ade的1.9.6文档读取与渲染代码：新项目可读取，去除新增字段后图层结构相等，渲染逐字节相等。旧版重新保存会丢失关联，文档明确说明。未增加模型、依赖或改变颜色引擎。

## 实际使用验收

原 `run.py`、完整 `Main.qml`、QTest offscreen/software，新独立应用进程，设置与恢复写入临时目录。实际点击图层改名、面部按钮、擦除范围、保存范围、PNG导出对话框；画笔减选通过真实前端Slot输入原图坐标，并非声称原生鼠标笔画测试。用户旧窗口保持打开，不覆盖Windows原生悬停/IME。

| 流程 | 实测结果 |
|---|---|
| ppp1605原4016×6016、本地 | 磨皮→改名→气色不增加图层；原磨皮及范围保留，一步撤销精确 |
| 修边后继续编辑 | 擦除一个已选皮肤区域、保存范围；精修复用同一层，手动范围逐项相等，其他层不变，一步撤销精确 |
| 保存重开 | 名称、身份、配方、范围持久化精确；再次气色复用原层 |
| 原像素与导出 | 变化388,651像素，修正范围外变化0；原像素tile和完整合成相等，实际PNG像素及ICC通过，导出3.416s |
| 旧读者 | 1.9.6真实文档模块打开新项目并渲染，像素逐字节相等 |
| AI双脸派生23.52MP | ppp1605+1602纵向派生图，保存的Qwen端点1HTTP、23.285s；上方自然柔肤25、下方曝光0.2EV，自定义独立层名，两张神经皮肤alpha与独立参考各自相等 |
| AI后手动继续 | 下方层改名、擦除、气色复用；原修边保留，上方层逐项不变，一步撤销精确，重开后精修继续复用，额外HTTP0 |

双脸派生图由同一女士的两张授权照片排布，不是新的真实多人准确率样本。两个原入口最终均源图与个人设置SHA不变，QML警告0，原应用与父进程退出0；已查看1.9.7本地精修和AI侧脸截图。该轮没有解决原有遮挡鼻部/脸颈语义遗漏，也不宣称识别质量已完美。
