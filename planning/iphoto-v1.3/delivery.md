# iPhoto v1.3 交付与验证记录

日期：2026-09-22。对应 [三大方向改造计划](redesign-plan.md)。本轮重构操作方式和选区数据，并落地本地算法、分区方案和缓存；保留 Qt / PySide6。

## 一、操作优化

- 左侧为浏览、矩形、椭圆、套索、魔棒、画笔工具；上方显示当前工具及新建/添加/减去等选项。
- 右侧“调整”“选区”独立，图层固定在右下。AI 选区使用自己的输入框，修图和建议仍在底部助手。
- 画选区先改变独立草稿，照片与原图层保持不变；输出为新调整层或明确替换当前层蒙版。
- 草稿有自己的撤销/重做，取消不删除原蒙版。新调整层默认全图，避免新建后什么操作都不生效。
- 点击图层蒙版缩略图载入修正。画笔默认添加；Shift/Alt 临时增减、X 切换、[ ] 改大小，工具快捷键避开文本焦点与模态设置。
- 输出/取消选区按钮固定可见。存在草稿时默认收起 AI 目标输入，优先露出边缘检查工具；需要重新识别可展开。底部助手可收起。
- UI 截图检查中修复缺失字形，改用自绘 SVG 工具图标；细化滑杆，扩展面板关闭按钮使用中文。

## 二、选区和分区修图

- 位图蒙版采用灰度 PNG 内嵌资源，最长边 2048、单资源压缩内容上限 2 MiB；支持孔洞、碎片与灰度边缘。形状/笔画仍可叠加；未知字段、类型、尺寸或非灰度 PNG 拒绝载入。
- AI 输出轮廓后默认进入 GrabCut 边缘优化。失败保留原轮廓，成功也能撤销回原始轮廓。覆盖面积异常和巨大偏离会提示；这不是语义准确率判定器。
- 魔棒使用相连颜色区域和容差，支持加选、减选。
- 本地主体分割已接入并测试 U²-Net 小模型；4,574,861 字节权重通过发布方校验，使用 OpenCV DNN CPU 推理，不读取 Key、不上传图片。
- AI 自动分区最多四区，每区有命名、理由、蒙版和参数。先预览与选择保留区域，再一次性建立独立图层；可以逐区优化边缘，整组一步撤销。确认前导出按钮关闭，避免导出与预览不一致。
- 给云端提供原图缩略图、当前黑白蒙版示意及已有层状态；蒙版 PNG 不放进文字 JSON。所有结果仍通过本地协议校验和受限渲染器。
- 项目升级为 1.3，兼容读取 0.1/1.2；保存矢量/位图蒙版、选区草稿、分区方案与对话。旧版应用不能读取新版项目。

## 三、能力扩展与性能

能力注册表位于 `src/iphoto/plugins.py`，区分算法、依赖、模型位置、运行方式与文档来源。算法在图像 worker 内延迟加载，界面不依赖具体模型。新增能力需显式注册，项目文件不能触发导入任意 Python 代码。

当前实际可用：GrabCut、魔棒、U²-Net CPU。缺少主体权重的环境显示配置入口；未安装时不会先创建空草稿再报错。模型安装脚本固定下载来源、校验内容并原子写入。

新加 64 MiB 像素缓存，缓存每个有效图层之前的合成结果。调整顶层时复用未变化的下层；切图清空缓存。蒙版查看和选区草稿继续复用已完成的照片预览。这个预算是缓存像素数据预算，不是整个进程内存上限。

SAM 2/3、PyMatting、Krita AI Diffusion/ComfyUI 已调研，尚未接入。基于本机 Intel UHD 集显、约 32 GB 内存的条件，优先 CPU 路线；后续大型分割与重绘采用独立服务适配。详见计划中的原始项目链接与许可区分。

## 验证结果

完整回归：**105 passed, 1 skipped，101.59 秒**。跳过的是没有正常 Windows 登录凭据会话时的真实系统凭据测试；随后在正常会话补测 **1 passed**，使用随机临时凭据并清理。因此本轮 **106 个不同测试用例**均已验证（跨两种执行环境）。

最后的界面细节修订后，额外重跑 8 个 Qt UI 用例全部通过；这些属于相同用例复测，不增加上述计数。

覆盖内容包括：

- 原有十二工具选区外像素/透明通道约束、原尺寸输出、图层顺序、历史与恢复错误保护。
- 草稿独立撤销、取消、输出新层、项目保存/恢复；分区全成功/全失败、取消、选择部分区域、整组撤销。
- 位图解码验证、孔洞、灰度、坐标、空结果、不支持能力、魔棒连通性。
- 真实 GrabCut 和真实 U²-Net 权重在 worker 中运行；AI 粗轮廓接本地优化的完整链路。
- 1440×930 与 1080×700 下的鼠标/快捷键、两个独立输入框、固定输出区、AI 设置和能力面板。截图等待图片真正加载后才保存。

云端协议用本机 HTTP 模拟服务测试，**未使用真实 Key 做云端识别验收**。本地模型实跑不是 Mock；分区与云端轮廓的语义质量仍需真人像、风景、室内样本验证。

## 性能与质量实测

见 [机器可读测量结果](../../artifacts/v13-benchmark.json)，由 `scripts/benchmark_v13.py` 复现。测量使用内置湖景缩至 1600×1066，三层调整；只计 CPU 合成，不包含 PNG 编码、进程通信和 QML 显示，也不是 2400 万像素导出耗时。

在其他测试结束后单独运行的三次顶层修改：无缓存 **971.0 / 996.7 / 1059.7 ms**，复用两个下层后 **375.5 / 389.9 / 379.3 ms**。中位数耗时降低约 **62%**；首次建立缓存 1319.9 ms。改动最底层仍需要重新合成其后的图层，不能承诺所有操作都有同样收益。

在 640×480、前景背景颜色明确、带内部孔洞的合成图上，粗框 IoU 为 **0.4702**，GrabCut 结果为 **1.0000**。这是简单可控样本的结果，不能推广为任意真实照片的准确率。

内置湖景的 U²-Net 实跑约 **1.9 秒**，主观观察主要选中了前景木屋，边缘与细结构仍不完整。没有该照片的标注蒙版，因此不报告真实照片 IoU。模型输入仅 320px，放大输出不会提升真实细节精度。

## 下一轮优先级

1. 用真实人像/风景/室内照片建立可复查的选区样本集，分别评价漏选、误选、发丝与边界修正成本；不能用测试数量代替效果。
2. 在相同样本上比较提示式 SAM 服务与轻量本地模型，增加点/框正负提示和 trimap/alpha 精修。
3. 曲线/色阶、修复与局部重绘、裁切变形需要新的数据和坐标契约，再接入相应工具；不能用现有十二参数假装完成。
4. 扩展仍以明确能力适配为单位；当前没有 PSD、8bf、任意 Krita 插件二进制兼容，也没有宣称 Photoshop 全功能。
