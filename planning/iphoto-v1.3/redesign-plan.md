# iPhoto v1.3：从功能集合改成修图工作流

日期：2026-09-22。依据本轮实际试用反馈制定；此前测试通过不代表操作体验或 AI 选区质量合格。

## 1. 操作优化：借鉴 Photoshop 的心智模型

目标是让用户知道“正在选哪里、正在改哪层、确认后会发生什么”。保留 Qt / PySide6 原生桌面路线。

| 区域 | 职责 | 交互约束 |
|---|---|---|
| 菜单、工具选项栏 | 文件、编辑、选择、视图；当前工具选项 | 工具选项随工具变化；快捷键不抢文本输入 |
| 左侧工具栏 | 浏览、框选、椭圆、套索、画笔 | 明确工具名称和快捷键；新建/添加/减去选区 |
| 中央画布 | 照片、蒙版预览、对比 | 选区草稿不改变成片；支持覆盖/黑白蒙版检查 |
| 右侧属性 | 调整 / 选区两个独立页 | 选区页有专用的 AI 选区输入；不会复用修图输入框 |
| 右侧图层 | 图层堆叠、选中状态、名称、透明度 | 一层一蒙版；可以把现有蒙版载入选区再修正 |
| 底部 AI 助手 | 修图、建议、自动分区方案 | 对话持久化；清楚标出当前作用范围；可折叠 |

选区流程：选择工具 → 绘制/AI 识别 → 补选、擦除、优化边缘 → 输出为新调整层，或明确替换当前层蒙版。取消草稿必须完整保留原图层。用独立的草稿撤销栈，避免画错一笔却撤销调色。

验收：在 1440×930 和 1080×700 两种窗口下完成导入、选择、输出图层、调色、撤销、保存；选区描述和修图描述互不串用；可直接找到作用对象。

## 2. 选区与分区修图能力

现状根因：视觉语言模型直接输出多边形，无法可靠表达发丝、孔洞、半透明边缘。增加提示词不能替代图像分割器。

本轮落地：

1. 蒙版支持受限尺寸的灰度位图，保留孔洞和细碎区域，并随项目保存；原有矢量选区继续兼容。
2. 接入 OpenCV GrabCut 本地图像边缘优化。AI 轮廓是初始提示，算法结合照片像素重新判断边界；保留原始草稿和撤销入口。不把 GrabCut 描述成语义模型或发丝级抠图。
3. 提供套索和颜色连续区域选择，补充矩形、椭圆、画笔；选区操作与蒙版应用分开。
4. 增加 AI 分区方案：最多四个明确命名的区域，每区有选区、参数和解释；先预览，各区可检查，确认后一次性建立独立图层。失败不产生半个方案，整组可一步撤销。所有像素修改仍由本地受限引擎执行。
5. 选区结果做空白、覆盖面积、原始轮廓差异检查；发现异常要明确提示并保留可修正草稿，不静默接受。

验收分为协议正确、像素范围正确、真实照片主观质量三类。Mock API 只验证流程；合成图可量化 IoU；真实人像/风景/室内质量尚需足够样本，不能以测试数量代替视觉效果。

## 3. 开源能力接入与性能

以能力注册表隔离 UI、AI 规划和具体算法。提供能力、依赖、运行位置、限制和可用状态；缺少依赖时不伪装成功。插件不读取 Key、不执行模型返回的代码，不通过项目文件加载任意 Python 模块。

| 候选 | 用途和判断 | 本轮处理 |
|---|---|---|
| OpenCV GrabCut / flood fill | CPU 可用，依赖较轻，适合初始轮廓与颜色边界；相似前景背景可能失败 | 实际接入、量化测试 |
| U²-Net 小模型 / rembg 发布的 ONNX 权重 | 主体/背景抠图；不能理解任意“只选左边杯子” | 本机已下载校验并实测，通过 OpenCV DNN CPU 执行；使用显式安装脚本，不在修图请求里下载 |
| SAM 2.1 | 点/框提示分割；官方建议 Windows 使用 WSL；依赖 PyTorch | 下一阶段独立进程/服务适配，先做硬件和样本验证 |
| SAM 3 | 文本概念分割更贴近自然语言选择；官方列出 CUDA GPU 和较新 PyTorch 要求，SAM 专门许可 | 候选评估，不作为默认安装依赖 |
| PyMatting | 从可靠 trimap 求 alpha，适合后续发丝边缘 | 在分割质量足够后接入 |
| Krita AI Diffusion / ComfyUI | 区域生成、局部重绘、候选结果交互可借鉴；Krita 插件不是可直接装进 Qt 应用的通用插件 | 学习流程；后续做独立服务适配，不宣称兼容 PS/Krita 二进制插件 |

性能优先做可测量的改进：缓存未变化的下层合成结果；蒙版修改不重做照片调色；模型延迟加载；限制预览尺寸和缓存内存。全尺寸导出独立评测，不能用低分辨率预览时间承诺导出速度。

## 执行顺序与交付边界

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| A | 独立选区草稿、位图蒙版、项目兼容 | 取消/撤销/重开不丢失；选区外不变 |
| B | PS 风格布局及快捷键、独立 AI 选区面板 | 两种窗口端到端 UI 测试及截图通过 |
| C | 本地优化器、能力面板、AI 分区方案 | 异常结果和依赖缺失有反馈；分区事务和对话记录完整 |
| D | 合成缓存、回归、实测、交付说明 | 测试通过，公布测量条件与未验收项 |

下一阶段：真正的提示式分割模型验证、trimap/发丝、曲线与色阶、修复/局部重绘、裁切与变形的坐标迁移、更多照片的盲测。这些不能仅靠增加按钮算完成。本轮不承诺 Photoshop 全功能、PSD/8bf 插件兼容或云端识别达到商业分割器水平。

## 本轮实施后的路线修订

硬件只读检查结果为 Intel UHD Graphics、约 32 GB 物理内存，没有独立 NVIDIA CUDA 显卡。当前优先 CPU 的 GrabCut / 魔棒 / 轻量主体模型；SAM 2/3 的后续验证优先考虑独立服务，不能把官方 GPU 吞吐指标当成本机指标。

U²-Net 已从预留接口推进到真实权重推理。模型输出为 320×320 的显著主体掩码，使用 OpenCV DNN，避免额外的推理运行库依赖。示例照片上的实跑与限制见交付记录；不据此宣称人像、室内、发丝或任意目标分割质量达标。
